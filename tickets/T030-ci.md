# T030 — CI: run `make check` on every push

**Depends on:** T025 (the `check` target), T026 (so the first green run means
something)
**Size:** S
**Touches:** `.github/workflows/check.yml`

## Why

There is no `.github/` in the tree. Every verification this repo owns —
`go build`, `go test ./...`, the mode-path existence check, the harness
symlink check — runs only when someone remembers to type `make check`.

The flag bugs in T026 are the argument for this ticket. `go test ./...` is
green on `ad9fcbd` and has been green throughout, while `newsops query` has
never once been invocable. Tests passing while the CLI is unusable is exactly
the failure CI does not fix by itself — but T026 adds the tests that would
have caught it, and CI is what guarantees they are still run in six months
when the next flag is added.

The symlink check earns this on its own. `make check` asserts that each
harness `SKILL.md` is a symlink (mode `120000`) resolving to the real file.
That is a property a contributor breaks accidentally — a checkout with
`core.symlinks=false`, an editor that dereferences on save — and it fails
silently: the skill loads stale content, or does not load, and nothing errors.
Now that `.claude`, `.cursor` and `.opencode` all point at one file, a
committed copy is a live drift risk.

## What to build

One workflow, push and pull_request, on the default branch.

```yaml
name: check
on: [push, pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version-file: go.mod
          cache: true
      - run: make check
```

`make check` is already the right entrypoint: offline, deterministic, and it
composes `build`, `test` and the two structural checks. Do not reimplement its
steps in YAML — a workflow that drifts from the local command is worse than no
workflow, because green CI then stops meaning "`make check` passes".

Notes for whoever implements it:

- **`go-version-file: go.mod`** rather than a pinned string. `go.mod` says
  `go 1.26`; one source of truth.
- **No cgo setup needed.** The driver is `modernc.org/sqlite`, pure Go, so
  there is no libsqlite3 to install and the job stays a plain checkout-plus-go.
- **`make sources` must not run here.** It hits 69 live feeds and one is
  already failing on latency (`rachelbythebay.com`, context deadline
  exceeded). Feeds rot independently of the code; a red build caused by
  someone else's TLS handshake trains people to ignore the badge. The
  `Makefile` comment already states this rationale — keep it true.
- **`git config core.symlinks`** is true on ubuntu-latest runners, so the
  symlink assertion in `make check` is meaningful there. It would not be on a
  Windows runner; do not add one without reworking that check.

## Acceptance criteria

- [ ] The workflow runs `make check` and nothing else.
- [ ] It passes on a clean checkout of the default branch.
- [ ] It fails when a harness `SKILL.md` is replaced with a regular file
      (verify by pushing that change to a scratch branch, then reverting).
- [ ] It fails when a `modes/*.md` referenced by `SKILL.md` is deleted.
- [ ] No network access beyond module downloads — `make sources` is not
      invoked.
- [ ] Go version comes from `go.mod`, not a literal in the YAML.

## Out of scope

- Release automation, tagging, or publishing a binary. `newsops version`
  currently reports `ad9fcbd-dirty` because no tag exists; creating the first
  tag is a human decision, not a workflow.
- Linting, coverage gates, matrix builds across OSes. One green signal that
  mirrors the local command, then reconsider.
- Anything that runs an LLM in CI.
