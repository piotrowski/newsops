# T031 — Bare invocation: a discovery mode, and the undocumented `voice-guide.md`

**Depends on:** T025
**Size:** S
**Touches:** `.agents/skills/news-ops/SKILL.md`, `AGENTS.md`

## Why

Two small gaps in what an agent sees at the moment it starts.

### 1. Bare invocation runs a 69-feed fetch

`SKILL.md`'s routing table maps `(empty)` to `modes/collect.md`. Now that the
skill is registered in every harness including `.claude`, the first thing
anyone types is `/news-ops` with no argument — and that fetches 69 feeds,
dedupes, ranks ~40 candidates, writes `digest.md`, and marks every one of them
`shown`.

`shown` is the part that makes this more than slow. It sets `stories.shown_at`
first-time-wins (T017), which is the repeat-suppression mechanism: those
stories will never appear in a digest again. So an exploratory keypress
silently burns a day of candidates. The action is not reversible through any
command the CLI exposes.

An agent cannot distinguish "run the daily collect" from "what is this thing"
when both arrive as an empty argument. career-ops routes empty input to a
discovery menu for this reason; news-ops routes it to its most expensive and
least reversible mode.

### 2. `context/voice-guide.md` is undocumented

`modes/draft.md:1` reads it, `modes/draft.md`'s last rule stops the whole mode
if it is absent, and `modes/voice.md:3` generates it. `AGENTS.md`'s "Where
Things Live" lists `context/` as "interests.md, beats.md, voice/ corpus" — the
one file that gates drafting is not in the table. An agent reading the table to
find out why draft mode refused finds nothing.

## What to build

### A discovery row in `SKILL.md`

| Input | Mode |
|---|---|
| (empty) | discovery — list the modes, report `newsops status --json`, stop |
| `collect`, `digest`, `news` | `modes/collect.md` |

Discovery is four lines in the router, not a file in `modes/`: name the
available modes with one clause each, run `newsops status --json` so the
freshness numbers are visible, and stop without touching the database. `status`
is `ReadOnly` with no lock, so it is safe to run unasked — which is the whole
point of routing here instead of to collect.

`collect`, `digest` and `news` keep routing to `modes/collect.md` unchanged, so
the daily loop costs one word and nothing about deliberate use gets slower.

Keep the router behavior-free, per T025: discovery lists and reports, it does
not judge. No ranking, no summarizing, no "here's what looks interesting".

### Two lines in `AGENTS.md`

Add `context/voice-guide.md` to "Where Things Live" — generated by
`modes/voice.md`, required by `modes/draft.md`. Note in the same row that it is
absent until the voice corpus reaches five samples, so its absence reads as
designed behaviour rather than a broken install.

While in that table: `docs/` is also missing from it. Add it if T028 has not
already.

## Acceptance criteria

- [ ] Bare `/news-ops` lists the modes, reports status, and writes nothing —
      no fetch, no `digest.md`, no `decide` call.
- [ ] `newsops status` is the only command discovery runs.
- [ ] `collect`, `digest` and `news` still route to `modes/collect.md`.
- [ ] Both human gates still appear verbatim in `SKILL.md` — T025's criterion,
      still binding.
- [ ] `SKILL.md` gains no judgment: diff it against `modes/*.md` and find no
      overlap.
- [ ] `AGENTS.md` "Where Things Live" lists `context/voice-guide.md`.
- [ ] `make check` passes — the mode-path grep must not trip over a routing row
      that names no file.

## Tests

Manual, fresh session, no prior context:

1. Invoke bare. Confirm the mode list and status, and confirm `digest.md` is
   unchanged and `unshown_stories` in `newsops status --json` is identical
   before and after.
2. Invoke `collect`. Confirm the full daily loop still runs and stops at the
   first gate.
3. Ask to draft with no `voice-guide.md` present. Confirm the refusal, and
   confirm `AGENTS.md` now explains why.

## Out of scope

- The voice corpus itself. `context/voice/` holds `README.md` and
  `EXAMPLE.md`; `modes/voice.md` correctly refuses below five samples and
  `modes/draft.md` correctly stops. Adding real writing samples is a human
  data task, as T025 already recorded.
- An `unshow` or `undo` command. Worth considering on its own merits, but the
  fix for accidental `shown` marks is not routing there by default.
- Harness-specific command files. A manifest that carries behavior is the
  drift problem T025 rejected.
